php-canvas：Layer 与 Renderer 分离 — 对象交互设计（待确认 · Renderer 驱动版）

目标架构：Renderer::render(Canvas)，Renderer 是主动方：由 Renderer 向 Canvas 拉取尺寸与有序图层， 按图层类型分派，读取 Layer 的"设定 + 纯布局函数"完成渲染。Canvas 是纯数据容器，只有访问器，不依赖任何 Renderer。

一、渲染主流程（对象交互时序）

二、静态类关系

要点：公开接口只有一个方法 render(Canvas): mixed；遍历/分派/偏移栈等通用逻辑收在 AbstractRenderer 模板方法里， 两个后端只实现 draw* 绘制原语，互不重复。特殊后端（如需自定义遍历/分页）可直接实现 RendererInterface 绕过基类。 Layer 与 Canvas 均不感知 Renderer，依赖方向永远是 Renderer → Canvas → Layer。

三、结构持久化 graph() / fromGraph()

关键决策点（请逐条确认）

#决策取舍
1Renderer 驱动：RendererInterface::render(Canvas): mixed 唯一入口Canvas 退为纯数据容器（只有访问器），不依赖任何 Renderer
2通用遍历收进 AbstractRenderer 模板方法（resolve→begin→walk→end）两个后端只实现 draw* 原语；特殊后端可直接实现接口绕过基类
3类型分派：Renderer 内 instanceof → protected draw* 方法不引入 visitor 双分派；新增后端=一个类
4布局计算留在 Layer（纯函数），不进 Renderer断行/对齐/autoHeight 两端共享，排版不分叉
5资源物化（下载、QR 生成）由 Renderer 在绘制前调 resolve 完成Renderer 只见本地路径；不再混入 setter
6容器下钻：Renderer 直画根表面 + 坐标偏移栈取代"子层渲染中间位图再 insert"，结果等价
7兼容：Layer::render() 保留为 deprecated 快捷方式（内部 new ImageRenderer 跑一遍）现有用户代码不断，最终移除
8graph() 补无损 + 新增 fromGraph()修三处有损：TableLayer 只存首行、字体只存 basename、QR 未生成时 value 为空

四、拆包评估（Renderer 独立成包）

结论：建议拆，但分两阶段——先在当前仓库内完成目录/命名空间分层（成本≈0），等 PdfRenderer 落地、 RendererInterface 经历一轮真实使用稳定后，再物理拆仓。

判据 / 放置细节结论
为什么拆依赖隔离是硬收益：intervention/image 的 ext-gd/ext-imagick 是全项目唯一 PHP 扩展硬依赖，PDF-only 用户不该背上；flysystem 核心+adapter 是成熟先例；第三方可实现 svg-renderer
RendererInterface + AbstractRenderer 放哪核心包——遍历/分派/偏移栈只依赖结构类型，放下游会逼后端包互相依赖或复制遍历逻辑
ResourceResolver（含 endroid）放哪核心包——QrCodeLayer 是结构层类型，任何后端都要物化，放下游会在每个后端重复
deprecated Layer::render() 兼容垫与"核心零感知渲染"矛盾：1.x 保留原样，2.0 拆包时随分离一起移除；BC 路径 $layer->render() → (new ImageRenderer())->renderLayer($layer)（renderLayer 放 image-renderer 包）
代价3 份仓库维护、跨包联动发版 → 契约标注 @api 严格 semver，后端包约束核心 ^2.0；核心包测试不再依赖图像扩展，driver 差异 hack 全留 image-renderer 包
拆包时核心 require收缩为 php + endroid/qr-code；suggest 指向两个渲染器包

迁移顺序（阶段化）

  1. 阶段一（同仓）：src/Renderer/（契约 + AbstractRenderer + Resolver）与 src/Renderer/Image/ 分层，完成迁移 1–3 步；
  2. 阶段二（同仓）：src/Renderer/Pdf/ 实现 PdfRenderer，用真实场景打磨接口；
  3. 阶段三（拆仓）：接口稳定后物理拆为 3 包，核心 require 收缩为 php + endroid/qr-code。
